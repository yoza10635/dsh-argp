# ARGP 定位与发文方向（v2 · 基于 06c 实测修订）

> 用途：ARGP 对外发文（论文 / 平台文 / RFC / 视频）的**方向与落点总锚点**。
> 派生关系：`publication-plan.md`（claims × 证据台账）应服从本文件的落点；本文件不替代台账，只规定"往哪个方向写、什么不再写"。
> 修订触发：06c 三层对照（A/B/C）跑完后，成本叙事与"完整保留"叙事均被数据证伪，故 v2 全面转向 assurance 定位。
> 状态：2026-08-23 定稿方向；角色扮演场景**明确排除**（当前小众，见 §8）。

---

## 0. 一句话落点（新 thesis）

> **ARGP 不替你赌什么不重要。**
> 当会话足够长、检索足够不可预知、精确性或不可逆不可妥协时，任何基于模型主观判断的有损压缩都会累积丢信息且不可逆；ARGP 用图结构判定安全边界 + 确定性 0-LLM + 可召回，把这种风险归零——代价是稳定溢价。

这是全文（无论何种形态）必须收口的句子。所有章节服务于它，不为它服务的章节砍掉。

## 1. 我们放弃了什么（诚实撤项 · 不可再写）

| 已撤主张 | 为何撤 | 数据来源 |
|---|---|---|
| **"ARGP 更便宜"** | 干净对照下 ARGP 比摘要式**贵 30–60%**。早期 ¥2.695 vs ¥3.087 的"便宜"对照物是带 bug 的失控基线（dsh high 档 77% 空流）+ 虚高 `hit=0` 口径，两数字皆不可信，已标记不可对外 | 06c A ¥1.135 vs B ¥0.819（4 次压缩同触发线）；scan-32k 旧成本字段 `undefined` |
| **"完整信息保留"措辞** | ARGP 不保留"完整"，只剪零入边原子；且大多数任务模型自外置状态（plan/todo/KB）或只需 gist，不需要那么完整。主打"完整"既不准确也不必要 | 用户战略复盘（2026-08-23）；06c R 针机制（见 §3） |
| **"多次压缩下成本反超"** | 数据不支持。跨档 A/B 成本比从 ~1.59×（1 次）收窄到 ~1.39×（4 次），B 仍便宜 39%，未反超 | 26（单压缩）+ 06c（4 压缩）配对 |
| **"占位改写 ≥ 摘要"作为通用结论** | 仅在"长 + 不可预知"场景成立；通用比较下摘要更省。降级为条件结论 | 见 §5 对 C3 的处理 |

**纪律**：任何对外稿不得再出现"ARGP 更省 / 更便宜 / 成本优势"类表述。成本只作为"稳定溢价 = 保真代价"的诚实披露出现。

## 2. 重新定义的优势（核心机制 · 这才是不变量）

两种压缩的本质区别不是"留多留少"，而是**谁来决定什么可以扔**：

| | 摘要式（BasicCompactionEngine） | ARGP（ArgpGraphEngine） |
|---|---|---|
| 删什么 | 模型**主观判断**"不重要" → 不可逆销毁 | 图结构判定"**零入边**才删" → 不赌、且可召回 |
| 失什么 | 被摘要"没选中"的细节永久丢失 | 仅删确定无人引用的原子 |
| 召回 | 无内置；加 grep 侧存档需读回大段 → 撑大上下文 | `recall_pruned` 从引擎内部 shadowed 日志找回，不撑上下文 |
| 风险 | **压缩器做错重要性下注** → 不可逆 | 移除该 Liability（不赌） |

**真正的卖点 = 移除"压缩器做错重要性下注的 Liability"。** 这是机制层不变量，代码可审、零成本可证，且是 ARGP 最不可替代的点。

## 3. 何时需要 ARGP（决策矩阵 · 发文必须给读者）

唯一变量：**未来会需要什么，现在能否预知？**

| 情境 | 能否预知未来检索 | 摘要式 | ARGP |
|---|---|---|---|
| 短会话 / 单任务（几次压缩） | 基本能 | ✅ 够用、更便宜 | 杀鸡用牛刀 |
| 模型已自外置状态（plan / todo / KB 文件） | 不需要上下文全留 | ✅ gist 够 | 溢价浪费 |
| 创作 / 探索类（要"感觉"不要精确） | — | ✅ | 无所谓 |
| **长 + 开放 + 检索不可预知** | ❌ 完全不能 | ⚠️ 赌错就丢、不可逆 | ✅ 不赌，等图证明安全才删 |
| **要精确原值**（代码串 / 数据 / ID / 决策原文） | ❌ 不知哪句会被引 | ⚠️ 摘要炖掉精确性 | ✅ 原样保留 |
| **不可逆不可接受**（审计 / 合规 / 回头复查） | — | ❌ 丢了找不回 | ✅ 可召回 |

甜区 = **长会话 × 高频压缩 × 检索不可预知 × 精确原值 × 不可逆不可接受** 同时成立的场景。
（注：编码 agent 因大量外置状态，反而稀释 ARGP 价值；纯聊天/角色扮演类因连续性全在上下文，是更干净的甜区——但**当前定位不纳入角色扮演**，见 §8。）

## 4. 06c 三层对照 = 新叙事的实证脊梁

同 80K/16K 触发线、同真实编码任务（大型代码库读取 / 读终端输出 / 多次改文件）、v4-flash：

| 指标 | A（ARGP，legacy） | A-density（ARGP，density 默认） | B（摘要式） | C（摘要 + grep 召回） |
|---|---|---|---|---|
| 压缩次数 | 4 | 5 | 4 | **8**（翻倍） |
| 成本 | ¥1.135 | ¥1.267 | **¥0.819** | ¥0.928 |
| 缓存命中 | 92.4% | 88.6% | 92.9% | 94.2% |
| U 针 | 7/7 | 7/7 | 7/7 | 7/7 |
| **R 针（保真）** | **7/7** | **7/7** | **2/7** | **7/7** |
| **recall 调用** | 0（needle 未剪） | **6/6 命中**（needle 剪后召回） | 0（不可逆） | grep 手动召回 |
| 摘要 error | 0（0-LLM） | 0（0-LLM） | 0 | **4/8（50%）** |

**读法**：
- B 最便宜但**丢信息**（R 2/7，早期 marker 被不可逆丢弃）。
- C 证明"给 B 加召回"能救回信息（R 7/7），但**结构性代价**：召回读回撑大上下文 → 压缩翻倍 → 摘要 50% error。朴素召回不解决根本。
- A 唯一同时拿到 **保真 7/7 + 确定性 0 错误 + 自动图感知召回 + 压缩不翻倍**。
- **A-density（当前默认）**：同保真 7/7，且是**唯一让 recall 通路真实跑通并 100% 命中（6/6）**的臂——density 剪掉含 marker 的大 artifact、逼模型用 `recall_pruned` 找回，直接实证了"图感知自动召回可逆"。代价是多一次压缩 + recall 注入 → 成本 +12%（非降本，是机制/质量升级）。
- 失败模式诚实自曝（C 臂 50% error）比任何外部 benchmark 更有说服力。

产物：`spike/out/06c-realistic-A2-*`（legacy）、`06c-realistic-A-density-*`（density 默认）、`06c-realistic-B-*`、`06c-realistic-C-*`。脚本：`spike/06c-realistic-coding.ts`（臂 A/B/C，`ARGP_ARM` 切换）。

> **完整原始数据脊梁**（组一次单压缩 160K + 组二多次压缩 80K + 跨频次模式 + density 分析）见 **`docs/argp-cost-fidelity-comparison.md`**——上表是其多次压缩组的摘录。

## 6. 三形态发文方向

| 形态 | 主 claims | 叙事骨架 | 核心句子落点 |
|---|---|---|---|
| **论文** | C1 + C2 + C4 + 诚实边界（§4） | 机制新颖性 → 确定性收敛 → 可逆性 → 06c 失败模式对照 | "我们移除的是压缩器做错重要性下注的 Liability" |
| **平台文 / RFC** | C2 + C4 + 决策矩阵（§3） | "你愿不愿意让压缩器替你赌什么不重要？" → 长会话场景演示 | §0 thesis |
| **视频稿** | §4 三层对照 | 06c 的失败模式现场：B 丢针、C 召回但崩、A 稳 | "便宜的代价，是丢不回来的信息" |

所有形态共用 §0 thesis 收口。

## 7. 质量叙事的公信力（低成本路径 · 不刷分）

细分赛道（compaction engine）reviewer 认**机制可审 + 诚实边界**，不认刷分。路径：

1. **零额外**：机制可审（C1/C2 架构属性）+ 06c 诚实边界（§4）。已就绪。
2. **低额外（可选，未做）**：RULER 协议结构的保真探针（短上下文塞针 → ARGP 压缩 → 问答），A/B/C 三臂同跑，预估 ¥10–30。买"协议公信力"但不端到端接 benchmark（benchmark 测模型非压缩器，性价比低）。
3. **高额外（不推荐）**：端到端开源长上下文 benchmark，¥100+，测的是模型不是压缩器。

**纪律**：质量只靠"机制透明 + 诚实失败模式"服众；若做探针，跑在"先经 ARGP 压缩、再回答"的自建管线上并诚实披露。

## 8. 明确排除

- **角色扮演 / 长期陪伴 bot 场景**：尽管按"状态外置度"维度它其实是比编码 agent 更干净的 ARGP 甜区（连续性全在上下文、压缩直接伤质量），但**当前定位暂不纳入**——属小众用法，待核心叙事站稳后再评估扩展。
- **"ARGP 更便宜 / 更省"**：永久撤项（§1）。
- **"完整保留"主导措辞**：改为"不赌重要性 + 保真不退化"（§2）。
