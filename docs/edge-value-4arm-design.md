# ARGP 边价值四臂验证实验设计（A 轨，台账 D20）

> 定位：把 D20 的四臂框架落成**可执行方案**——复用既有资产、精确到改哪几个文件、算清成本、预置判决标准。
> 状态：【纸面设计】，待用户拍板执行档位后实现。
> 前置判决：本实验裁决 D2 遗留的【未测】假设——**边到底有没有可测量的价值**。判决结果决定搭车复核协议 C 协议（质量档）建不建。

## 0. 复用资产盘点（省掉"从零建"）

探索代码后确认三块关键资产已存在，本实验是在其上**加探针 + 加开关 + 加重放**，不是新建：

| 资产 | 位置 | 复用点 |
|---|---|---|
| 长程骨架（needle 编码 / 契约注入 / recall 归属 / targetShadowed 判定） | `spike/06-tlong.ts` | D 针探针的编排与判法直接套用它 |
| **零 LLM 成本离线重放** | `spike/28-simulated-replay.ts` | 读 events.jsonl、跳过 compaction 事件、逐 user/message 调 `compactIfNeeded()` 复现压缩序列——A₁/A₃ 臂的保留集对比全靠它 |

## 1. 重要修正（相对 D20 框架，探索代码后发现）

### 修正 A：执行成本不是"1 次会话"，是分档（D20 表述需收紧）

D20 写"四臂只多花一次会话的钱"——**不严谨**。LLM 行为（有无契约 / 有无 cites 文案）会改变模型 recall 决策，所以：

- **A₂（契约+模型 cites）必须真跑**（唯一完整臂）
- **A₁（契约无边）的 D 针正确率里"被剪后 recall 找回"那部分也依赖 LLM 行为**，离线算不了 → 要拿完整 P2 判决，A₁ 也得真跑
- A₀（无契约无边）是辅助基线（理解"无提醒时模型自发 recall"），**可后置/省略**
- A₃（oracle 边）保留集 + D 针可达性**完全离线**（28 重放）

故分两档执行（见 §7 成本）。

### 修正 B：剪枝是**原子级**不是行级——D 针埋点设计要改

D20 写"承载放 R 原子中段行 = 边独占贡献区间"——**有误**。剪枝按 seq 整原子剪（R 原子 = 一个 tool/result 全文），中段行不能脱离 R 原子被单独保留。

故 D 针设计修正为：**选择特定的早期 R 原子**（某个 chunk 的 tool/result），让 D 针答案依赖这些 R 原子的内容。边的作用是"保住整个 R 原子（含答案数据）"，不是"保住某一行"。D 针比现有 R 针严在：答案是**综合 ≥3 个 R 原子**、且模型**不被直接告知 chunk 号**。

### 修正 C：离线/真跑的精确边界

| 命题 | 离线可算 | 需真跑 |
|---|---|---|
| P1 结构层（边是否改变保留集） | ✅ 全部（28 重放：清边 vs 带边 vs oracle 边，比 shadowedSeqs） | — |
| P2 信息层（D 针正确率） | 仅"全保留 probe"贡献（碎片 R 原子都在 surface → 直读） | "被剪后 recall 找回"贡献 |
| P3 成本层（recall 频率） | — | ✅ 全部（recall 是 LLM 行为） |

A₃ 的 D 针正确率可**离线逼近**：oracle 边保证碎片 R 原子保留 → 正确率 ≈ 保留集里碎片 R 原子全在 surface 的 probe 占比。

## 2. 命题分层（P1/P2/P3）

| 层 | 命题 | 失效后果 | 测量 | 执行方式 |
|---|---|---|---|---|
| P1 结构层 | 边是否真改变剪枝保留集 | 边是死代码，后全免谈 | 同 events 清边 vs 带边重放，比 shadowedSeqs 差异 | **离线** |
| P2 信息层 | 边保护的 R 原子是否恰是 D 针需要的 | 保了没用的/剪了有用的 → 边是负资产 | D 针正确率（3 个碎片 R 原子全可达才算对） | 真跑 + 离线混合 |
| P3 成本层 | 保护是否转化为 recall 调用下降 | 保护没省调用 → 价值打折 | recall 调用计数对比 | **真跑** |

## 3. 臂设计（4 臂 → 真跑/离线映射）

| 臂 | 契约 | 边 | 执行 | 测什么 |
|---|---|---|---|---|
| A₂ | 有 | 模型 cites | **真跑** | 完整基准（events + D 针 + recall + 保留集） |
| A₁ | 有 | 无 | **真跑**（P2/P3）+ 离线对照保留集 | 行为引导的独立贡献；**真实边价值 = A₂−A₁** |
| A₀ | 无 | 无 | 可选（后置） | 裸 recall 基线（无提醒下界） |
| A₃ | 无 | oracle 边 | **离线**（28 重放 + oracle 边注入） | 理论上限；**A₃−A₂ = 模型服从率吃掉的价值** |

**A₃ 是便宜臂**：取 A₂ 同一份 events.jsonl，oracle 边（离线辅助 LLM 组图，schema 强制、前向全上下文）注入后重放剪枝——零会话成本。一臂同答"边上限多大" + "周期/阈值组图理论可拿到多少"。

**关键近似误差披露**：A₁ 的 D 针正确率离线只能算"碎片 R 原子全保留"那部分；"被剪后 recall 找回"那部分必须真跑。若只做经济档（只跑 A₂），A₁ 用离线保留集近似会**低估**其正确率（漏算 recall 找回）——判决 A₂−A₁ 会偏保守。

## 4. D 依赖针设计（核心新增探针）

### 与现有针的区别

| 针 | 承载 | 测什么 | 对边的鉴别力 |
|---|---|---|---|
| U 针 ×7 | archival note（U 原子，永不参剪） | 载体保护 | 无（U 永保） |
| R 针 ×7 | chunk 首行 marker（单个 R 原子，recall 找回，文案直接告知"读过的 chunk"） | recall 闭环 | 弱（单点 + 直接提示） |
| **D 针 ×3（新增）** | **3 个早期 chunk 的 telemetry 统计（综合，模型不被告知 chunk 号）** | **跨轮综合保留** | **强（综合 + 模糊提示）** |

### 埋点（利用现有 chunk 数据，不改 makeChunk）

现有 `makeChunk(i)` 生成的 150 行 telemetry 本身含 `shard=(n+i)%16`、`queue=(n*3+i)%50`、`level=WARN (n%13===0)` 字段。D 针直接取**早期 3 个 chunk**（建议 chunk 2/5/8，对应 filler 轮 3/6/9，新近度最低、最易被剪）的 shard 统计作答案来源。

**探针有效性预检（必须先跑）**：在 A₁/A₀（无边）保留集里确认这 3 个 R 原子**确实被剪**（targetShadowed=true）、在 A₃（oracle 边）保留集里**确实被保留**。若前提不成立（这 3 个 R 原子本就不被剪 → 探针无鉴别力），重选埋点（更早的 chunk）。**这一步是 D 针成立的前提，不通过则探针无效。**

### 问法（适度提示，不给 chunk 号）

> 综合你之前读过的 telemetry chunk，哪些 shard 号**同时**满足 `level=WARN` 且 `queue>40`？逐个列出。若需要被剪的 chunk 内容，先用 recall_pruned 找回相关 placeholder 再作答，不要猜。

### 判法

D 针 k 正确 ⟺ 模型列出的 shard 集合 == 脚本侧预计算的期望集合（3 个 chunk 的 telemetry 里 WARN 且 queue>40 的 shard 并集，去重）。脚本侧在 makeChunk 时即可离线算出期望值（确定性伪随机，同 uToken 持有法）。

## 5. 工程实现清单（具体改哪）

1. **`06-tlong.ts` 参数化两个开关**（环境变量控制）：
   - `ARGP_CITES_ON`（默认 true）：关 → fillerBody 去掉"append the ARGP citation block"句（A₁/A₀ 臂）
   - `ARGP_CONTRACT_ON`（默认 true）：关 → 撤契约注入（A₀ 臂）。**待确认项 1**：契约注入机制（argp-contract 独立插件 vs 引擎 system reminder），参考 `11-contract-probe.ts` 的 disabled 臂配置。
2. **`06-tlong.ts` 加 D 针**：选 3 个早期 chunk 作 D 针源 + D 针 probe 文案（§4）+ 离线算期望 shard 集合 + D 针判法（§4）+ **探针有效性预检**（§4，A₁ 保留集对比确认 R 原子被剪）。
3. **`argp-graph-engine.ts` 加 oracle 边注入 seam**：`ArgpGraphConfig` 加 `injectEdges?: (atoms: Atom[]) => SemanticEdge[]`，`buildGraph()` 在算完 cites 边后调用它合并（~10 行）。A₃ 臂用此注入 oracle 边；A₁/A₀ 臂不注入。
4. **复用 `28-simulated-replay.ts`**：扩展为支持"清边 / 带原 cites 边 / oracle 边"三种边源重放，输出 shadowedSeqs 差异（P1）+ 碎片 R 原子可达性（P2 离线部分）。
5. **聚合输出**：D 针正确率、recall 调用计数、保留集差异、citeStats，写 result.json。
6. **离线 oracle 边生成脚本**：辅助 LLM（schema 强制、function calling 形态）读 A₂ events 的轮摘要，输出边集（from→to + level）。成本 ~¥0.05–0.2 一次（前缀缓存 hit），跑完过 `.tmp/cost-audit.mjs` 实测。

## 6. 判决标准（预先写死，防事后找解释）

| 结果（D 针正确率差） | 判决 | 动作 |
|---|---|---|
| A₂−A₁ < 5% | 模型边无保留增益 | **边投入止损**：每轮 cites/周期复核/阈值组图全停，叙事收缩为"0-LLM 剪枝 + recall 兜底"（已证、足够） |
| A₂−A₁ ≥ 5% 且 A₃−A₂ 差距大 | 边有效但模型边太烂 | 值得建质量档（= C 协议搭车复核），方向 = 周期/阈值组图 |
| A₃−A₀ < 5%（完美边也无增益） | 剪枝靠 selfImportance+新近度已足够 | 全停（D6"U 载体+重推导"支柱成立到边多余的程度） |
| 全臂 recall 频率无差异 | P3 不成立 | 边价值仅限保真，成本叙事不写 |

P1 独立判决：若 A₂ 带边重放 vs A₁ 清边重放的 **shadowedSeqs 完全相同** → 边是死代码（P1 不成立），P2/P3 免测直接止损。

### 决策价值矩阵（2026-08-24 讨论补记：本实验对"是否转向多向边"能切掉什么）

本实验测的是**廉价 cites 前向边**，不直接定价多向边；但 A₂×A₃ 两个信号组成 2×2，覆盖转向决策的大部分空间：

| cites 增益 A₂−A₁ | oracle 上限 A₃−A₁ | 对转向的决策含义 |
|---|---|---|
| ≈0 | ≈0 | **整个"边"方向死掉**——cites 契约停维护 + 多向边不投，转向其他机制（廉价杀方向，最高价值） |
| ≈0 | >0 | 边价值存在但廉价声明抓不住 → **投多向边/更贵的边构建**（本实验直接给出投资理由） |
| >0 | ≈0 | cites 已抓满价值 → 保留 cites，**不投**更贵的边 |
| >0 | >0 | 机制验证 + 有剩余空间 → 多向边是**增量优化**，按余量大小定投入档 |

**局限与补救**：当前 oracle（§5.6）是依赖式组图，行 2/4 的"上限"只覆盖依赖式边；多向边可能更高。补救成本低——A₃ 组图 prompt 扩展"跨 checkpoint 链接/水平关联"约束即可，**该扩展列为 A₃ 跑前可选前置项**，做了则本实验覆盖完整转向决策。

## 7. 成本与墙钟（分档）

| 档 | 执行 | 成本（v4-flash 空闲价） | 墙钟 | 拿到 |
|---|---|---|---|---|
| **完整档** | A₂ 真跑 + A₁ 真跑 + A₃ 离线 + A₀ 可选 | ~¥6（2 次真跑）+ ~¥0.2（oracle 边） | ~2.7h（2×80min 串行 + 离线秒级） | P1+P2+P3 完整判决 |
| **经济档** | A₂ 真跑 + A₃ 离线（A₁ 用离线保留集近似，A₀ 省略） | ~¥3 + ~¥0.2 | ~1.5h | P1 + A₃ 上限 + P2 近似（A₂−A₁ 偏保守） |

> 建议先跑**经济档**：P1（保留集差）+ A₃ 上限若已足以判决（如 A₃−A₀ <5% 直接全停，或 A₂−A₁ 近似值已 ≥5%），就不必花 A₁ 真跑的钱。经济档判"边无价值"是硬判决（离线 P1 可信）；判"边有价值"需完整档的 A₁ 真跑确认 P2/P3。

## 8. 风险与近似

- **A₁ 正确率近似误差**（经济档）：离线漏算"被剪后 recall 找回"→ A₂−A₁ 偏保守（可能漏报边价值）。方向已知，完整档可纠。
- **探针有效性**：若 3 个早期 R 原子在无边时本就不被剪，D 针无鉴别力 → 预检不通过则重选埋点（这是 §4 的前置步骤）。
- **oracle 边质量**：辅助 LLM 组图的 schema 服从率（function calling 形态，D1 确认可靠区间，但具体数字跑前不可知）。若 oracle 边覆盖不到碎片 R 原子，A₃ 上限被低估。
- **与 160K 契约分离实验的关系**：160K disabled 臂 R 1/7 FAIL 的归因（"图缺边保护" vs "模型少了每轮 provenance 提醒不主动 recall"）本实验的 A₂−A₁ vs A₃−A₂ 拆分正是要拆的——160K 用的是 R 针（单点），本实验换 D 针（综合）更严。
- **边类型外部效度（2026-08-24 讨论补记）**：本实验测的边 = **模型声明的前向 cites 边**（回复→依赖的早期原子；向后指、单跳、回复时声明、零额外成本）。设计路线图后续的 **checkpoint 间原子多向边**（跨压缩边界的前/后/水平链接，需 aux LLM 或确定性跨 checkpoint 构建，**有额外成本**）是**结构不同的另一类边**，价值可能完全不对等——cites 天然丢失跨 checkpoint 链（压缩后可见的是摘要/tombstone，新 cites 引用摘要而非原原子）。**本实验结论的适用范围 = "廉价 cites 边是否有保留价值"，不能外推到多向边**。解读守则：P2/P3≈0 → 只证 cites 边死代码；是否投多向边看 A₃ oracle 余量（且 oracle 须扩展覆盖多向边才是该问题的真上限）；P1/P2/P3 门控与边类型无关，未来多向边可直接复用本四臂框架。
