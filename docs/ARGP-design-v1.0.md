# ARGP：原子引用图剪枝式上下文压缩 — 设计基准（外部验证版）

## 1. 文档信息
| 项 | 值 |
|---|---|
| 版本 | V1.8 |
| 日期 | 2026-08-09 |
| 状态 | 待外部验证 |
| 代号 | ARGP — Atomic Reference Graph Pruning |

## 2. 摘要（TL;DR）
ARGP 将对话历史拆分为带全局编号的"原子"（用户输入 U / Agent 输出 A / 工具调用 T / 工具返回 R），每轮由 LLM 结构化声明原子间的引用关系（critical/supporting/contextual），应用层据此构建有向"引用图"；压缩时以纯算法按"孤立→contextual→supporting→critical"的反向拓扑序摘除原子直至 token 达标，**压缩阶段 0 次 LLM 调用**。上下文渲染采用**编号内联**（保留原子呈现为 `[编号] 内容`），索引税 10–15% → 0，LLM 只能引用眼前可见编号、杜绝幻觉引用，被剪原子统一经 recall 访问。预期收益：每轮 20–40 token 的"标注税"、压缩可审计可恢复、**压缩率可控且可收敛**——每个原子 token 已知、剪枝确定性、降级循环直到达标（摘要原子可设目标长度），而摘要式（SDK compact）压缩率不可控、不保证收敛。代价：引入 LLM 引用可靠性与编号内联可用性两个待验证假设。

## 3. 背景与动机
摘要式压缩（如 Pi SDK session.compact）在压缩时用一次全量 LLM 调用把历史重写为摘要：成本随上下文线性放大（约占 20–50% 上下文 token）、有信息损失、不可审计。ARGP 的思路：**不重写历史，而是选择性遗忘**——让依赖关系在对话发生时以结构化形式沉淀（标注税，平摊到每轮），压缩时只需按图拓扑规则摘除原子，无需 LLM。本质是"把一次性成本换成持续小税"。

## 4. 术语表

|---|---|

| 引用边 | 有向边 结论→依据，带等级 critical/supporting/contextual |
| 确定性边 | 由 SDK 事件流自动生成的边（A→T、T↔R），无等级 |

| 编号内联 | 渲染上下文时保留原子呈现为 `[编号] 内容`，编号随内容可见、零额外 token；替代索引注入 |

| lastRefRound | 原子最近一次被引用的对话轮次；创建时自引用初始化为创建轮次 |
| 摘要原子 | summarize-critical 生成的替代原子，承接被替代闭包的 critical 边与信息承载 |
| 降级策略 | 常规剪枝不达标时的兜底序列 summarize_critical→force_prune→fail（可配置） |

| 处置策略 | closureDisposition ∈ {memory,tips,tombstone}，闭包 PRUNED 的落点配置，可全局或按闭包类型 |

## 5. 方案设计

### 5.1 原子模型
- 四类原子：U(用户输入)、A(Agent 输出)、T(工具调用)、R(工具返回)
- 编号全局单调递增、永不复用；被剪原子编号保留（保证引用稳定性）
- 元数据存应用层映射表（不塞进 messages）：`{id, type, contentRef, tokens, selfImportance, createdAt, lastRefRound}`
- **lastRefRound 初始化**：原子创建时 `lastRefRound = 创建轮次`（**自引用一次**），新原子初始最近引用距离 = 0，自动与新鲜度保护对齐，无需特判
- **双通道建边**：
  - 确定性边：T↔R、A→T 由 SDK 事件流自动生成（零成本、100% 可靠）
  - 语义边：A→U、A→R、A→A 由 LLM 输出时声明（JSON schema 结构化，见 5.2）

### 5.2 引用分级体系（剪枝第一排序键）
| 等级 | 含义 | 剪枝顺序 | 边权重 |
|---|---|---|---|
| （无引用）孤立 | 无任何关联边 | 最优先 | — |
| contextual | 上下文关联，帮助理解 | 优先剪 | 2 |
| supporting | 辅助依据，提供背景 | 中间剪 | 5 |
| critical | 核心依据，摘除→结论崩塌 | 最后剪 | 10 |

LLM 每轮输出末尾附（JSON schema 强制）：
```json
{"refs":[{"to":"U12","level":"critical"}],"importance":7}
```
设计理由：边等级是相对判断（该结论依赖谁的强弱），比重要性绝对值更稳定、跨模型可复现，故为第一排序键；importance 仅作同等级内 tie-break。

**refs 生命周期（V1.8，直接改造）**：当轮 refs 由 LLM 输出时声明；assistant 消息落盘时解析尾部 refs JSON（容错，失败兜底为空 refs）写入该 entry 的 details 元数据，并从渲染文本剥离——历史 refs 不重复进上下文；会话 reload/分支导航后可由 details 完整重建语义边。

### 5.3 三条逻辑不变量（自洽性核心）
**不变量 1 — 推导重要性（解决打分漂移）**：
```
effective_importance(a) = max(selfImportance(a), max(指向a的边等级权重))
```
原子自身打分可能漂移（同一事实在不同轮被低估/高估），但被 critical 边指向意味着"有结论离不开它"，用入边最大权重兜底，使关键依据永不因自评低而被误剪。

**不变量 2 — critical 闭包守恒**：
critical 边指向的原子必须保留，直到该边自身消失（即引用方也被剪除）；**唯一例外（closure exemption）**：若依据方 U_i 满足 askCover(U_i)（见 5.7，基于原始图判定），则 U_i 可先于该边消失被剪除，其信息由覆盖方 A_{i+1} 承载。等价表述：`∀ 边 e=(x→y, critical)：若 x∈K 则 y∈K ∨ askCover(y)`。剪枝只能摘除"结论方"，critical 依据方的存续由引用方背书，形成整体保留的闭包。

**不变量 2′（V1.5，闭包级移除规则）**：原不变量 2 形式不变——它已允许"结论方 x 被剪后依据方 y 可剪"，闭包整体剪除只是把该动作**原子化**到整个闭包。新增规则：`闭包 C 整体移除合法 ⟺ 边界无外入 critical 边（∀ critical 边 x→y，x∈K ∧ y∈C ⇒ x∈C），即闭包 in_degree==0`。剪除顺序：先原子级正常剪（不变量 3）→ 候选耗尽时按闭包 DAG **叶序**剪 COMPLETED 闭包 → 全部剪完仍不达标才落 summarize-critical。闭包生命周期见 5.11。

**不变量 3 — 反向拓扑剪枝**：
可剪候选 = 当前入边为空的原子（无任何结论依赖它）；剪除后其出边消失，指向的原子入边减少，可能成为新候选，循环直至 token≤预算。由此保证"先剪结论方，才能剪依据方"——依据方只在所有依赖它的结论都被剪掉后才可剪。

### 5.4 剪枝算法
```
function prune(G, T):                     # G=原始引用图, T=token预算
  K = 全部原子
  askCand = 静态标记 {u∈U | askCover(u)}    # 基于原始图预分类，非最终判定
  while Σtokens(K) > T:
    candidates = {a∈K | in_degree(a)==0}
               ∪ {u∈K | askCand(u) ∧ coverer(u)∈K ∧ u≠最新U}   # ask 豁免候选
               − 新鲜度保护(最近1轮的A/R原子)      # 保护近期结论不被误剪
    if empty:                       # 进入降级循环（5.9）：持续降级直到达标
      action = degrade(K, G)
      # summarize_critical → 生成S+重定向→chain入候选→回主循环继续剪
      # force_prune → 强制剪最弱critical（保留最新U）+审计日志+报警→回主循环
      # fail → 单原子超窗/资源用尽，报警并终止（提示新会话）
      if action == fail: break
      continue                    # 每次降级动作后回主循环重剪
    sort candidates by:
      ① 关联边最低等级(孤立 < contextual < supporting < critical)
      ② effective_importance 升序
      ③ lastRefRound 升序（最近引用距离大的先剪；创建时自引用使初始距离=0）
    a = candidates[0]
    K -= {a}; 记录剪枝日志{a, 等级, importance, 原因:[ask_exempt|normal], 剩余token}
  return K
```
- **0 次 LLM 调用**（常规路径）；确定性边不参与等级排序（无等级边原子与孤立同级优先剪）
- **lastRefRound 维护**：每次新增入边 e=(x→y) 时 `lastRefRound(y) = max(lastRefRound(y), round(x))`，单调不减；建图 O(E) 一次算完，剪枝只读（见 5.8）
- 被剪原子仍在 JSONL：**剪枝=发送视图，非物理删除**，可审计、可恢复、可回滚（恢复通道见 5.10）
- 常规剪枝以预算达标为目标；**candidates 耗尽仍未达标时进入降级循环（见 5.9）：每次降级动作后回主循环重剪，直至 token≤T 或命中三硬终止条件**，不再"宁超预算"

### 5.5 头脑风暴模式
| 模式 | 引用声明 | 编号渲染 | 剪枝依据 |
|---|---|---|---|
| 普通 | 强制（schema 必填） | 内联（零额外 token） | 图剪枝（强一致） |
| 头脑风暴 | 可选（缺省 contextual） | 内联（同普通） | 降级为 importance 排序（概率性） |

头脑风暴场景语义松散、引用价值低，允许省掉部分标注税（编号内联本就 0 成本、无索引可省）；代价是剪枝退化为概率性保真，仅适用于低风险发散场景。

### 5.6 成本核算
| 项 | ARGP | 摘要式 / SDK compact |
|---|---|---|
| 标注税（每轮） | 20–40 token | 0 |
| 索引税 | 0（编号内联，零额外 token） | 0 |
| 压缩成本 | 0（纯算法） | 全量 LLM 调用（20–50% 上下文） |
| 降级成本 | 0（常规）；不达标时 summarize（上限 N=3 次/单次剪枝，每次一次 LLM）→force-prune（0 LLM）→fail | 0 |
| 处置成本 | tombstone 0；tips 0 LLM（复用结论首句），上下文常驻一句话（可后续剪除）；memory 0 LLM 组装摘要 + 1 次 writeClosureMemory 外部调用（embedding/存储成本计入 memory 实现方，ARGP 侧仅钩子） | 摘要式：无对应（整闭包已进摘要） |
| diff 去重收益 | 0 LLM；高重叠 R 只留 1 份（压缩率↑），recall 频次↓ | 摘要式：无对应（全量进摘要，重叠仍在） |
| KV 缓存 | 剪枝破坏前缀缓存（一次性重算）；稳态每轮成本 ∝ 上下文长度，压缩率↑→每轮递减 | 摘要同样破坏前缀缓存，且压缩本身为一次性大 LLM 调用 |
| 压缩延迟 | ~0ms | 一次完整 LLM 往返 |
| 信息保真 | 原子级无损（视图剪枝） | 摘要有损、不可审计 |
| 压缩率可控性 | **可控且可收敛**：原子 token 已知 + 剪枝确定性 + 降级循环直到达标（可验证） | 不可控：摘要 token 数取决于模型，可能压不足/压过头，不保证收敛 |

结论：ARGP = 持续小税 + 零压缩 + 压缩率可控可收敛；摘要 = 平时零税 + 压缩大爆发 + 压缩率不可控。**KV 缓存维度**：上下文被剪枝改写后前缀 KV 缓存必然失效（保留集变化，后续轮次要重算 attention）——保留更多原子不会带来 KV 收益；稳态每轮推理成本 ∝ 上下文长度，压缩率越高每轮成本越低。但压缩率↑ → 信息丢失↑ → recall 召回频率↑ → 每次 recall 有注入 token + KV 重算成本，故存在平衡点：压缩率应趋近"信息保真下限"（不触发频繁 recall 的最高压缩率），而非无限高。长对话/频繁压缩场景 ARGP 占优；force_prune/fail 为小概率兜底，不改变上述结论。

### 5.7 U 原子分类与 ask 覆盖检测（逻辑支撑层）
**定位**：本节提供逻辑判定与剪枝语义，供实现参考；**非本期实现需求**。

**ask/task 定义**：task U=命令型输入，信息需跨轮被多个 A 反复引用（如"分析Q3营收下降原因"）；ask U=询问/轻量请求型，当轮即被首个 A 回应并吸收（如"写周报结论"）。分类由判定式自动推导，不依赖人工标注。

**判定式（形式化）**：
```
round(U_i) = [U_i, nextU)                # 一轮 = U_i 至下一 U 之前
A_{i+1} = round(U_i) 内第一个 A 原子       # 紧邻后继；其间可含 T/R，不可含 U
askCover(U_i) ⟺ A_{i+1} 存在
              ∧ in_edges(U_i) ⊆ {A_{i+1}→U_i}   # 全部入边来自紧邻后继
```
注：以"入边来源集合"为准，同轮后置 A 与跨轮 A 均使判定不成立（存在任一非 A_{i+1} 引用者即非 ask）。

**closure exemption 豁免规则**：若 askCover(U_i)，即使 A_{i+1}→U_i 为 critical，U_i 亦可被剪除（其信息由 A_{i+1} 承载）。
- 守卫：豁免剪除仅当 A_{i+1}∈K（剪枝时动态判定）；askCover 标记基于**原始图**静态预分类。
- 顺序：豁免剪除不改变 A_{i+1} 入度；若 A_{i+1} 先被剪，U_i 入度归零、回退普通候选。
- 新鲜度：豁免不适用于"最新一条 U"（保留用户最近原话）；A_{i+1} 处于新鲜度窗口时豁免收益最大。

**与三条不变量的关系**：① 与不变量 1 互补——豁免在 effective_importance 之后作为闭包例外生效；② 豁免是 critical 闭包**唯一允许的例外**（见 5.3 修订）；③ 候选集扩展为 `{in_degree==0} ∪ {askCover ∧ A_{i+1}∈K ∧ ¬最新U}`，豁免 U 关联边等级仍为 critical→排序垫底（最后兜底剪），符合"宁可错留不可错剪"。

**预分类 vs 动态判定（实现取舍，非实现需求）**：预分类（建图时 O(E) 扫描）只能做预筛，守卫必须剪枝时复核；推荐"静态标记+动态守卫"。可选语义增强：LLM 声明 refs 时附 `covers:true` 标志（+2~4 token/轮）可将误判率降至近零，列为后续选项。

### 5.8 时间降级维度
- **定义**：排序键 ③ 用"最近引用距离"取代 createdAt；距离 = 当前轮次 − lastRefRound，越大越先剪（等价 lastRefRound 升序）。createdAt 保留作审计，不再参与排序。
- **维护规则**：原子创建时 `lastRefRound = 创建轮次`（自引用一次，初始距离=0）；每次新增入边 e=(x→y) 时 `lastRefRound(y) = max(lastRefRound(y), round(x))`，单调不减；建图 O(E) 一次算完，剪枝只读。
- **语义**：距离 0 = 刚创建或刚被引用（软保护）；距离大 = 久未活跃，优先遗忘。度量的是**活性**而非年龄——早期原子若持续被引用，距离保持小，不会因"出生早"被误剪。
- **与 askCover / 新鲜度保护 / 最新 U 的交互**（审查结论，均无需修改判定逻辑）：
  - askCover：豁免 U 的唯一引用者 A_{i+1} 与其同轮 → lastRefRound 自然成立；豁免 U 等级仍 critical 排序垫底，lastRefRound 仅在 critical 内部 tie-break，不改变豁免语义
  - 新鲜度保护（硬过滤：最近 1 轮 A/R 移出候选集）与软排序（候选内次序）作用阶段不同，无冲突；对最近轮 A/R 略有重叠，但硬规则更严格，两者保留
  - 最新 U 除外（硬排除，语义保护）与 lastRefRound=0（软保护）方向一致，叠加无冲突

### 5.9 超预算降级策略
**动机**：常规剪枝"宁可超预算也不破不变量"在产品中不可接受——context window 溢出导致 API 报错、任务崩溃，比丢信息更严重。必须准备兜底序列。

- **层级 0 预防**：压缩目标 `T = window − reserve`（默认 `reserve = 25%`，输出长时 `≥max(output_max, 20%)`），从源头防止压缩后输出溢出。
- **触发条件**：主循环 candidates 为空 且 `Σtokens(K) > T`。
- **循环语义（V1.5 更新）**：降级不是"尝试一次"，而是**持续降级循环直到 token ≤ T_max**（达标）：
```
while Σtokens(K) > T:
    生命周期剪除（5.11）：PRUNABLE 闭包按闭包 DAG 叶序整体移除（0 LLM）
    无 PRUNABLE 闭包 → summarize-critical（生成摘要原子 S 后回主循环继续剪）
    summarize 达上限 N 仍不达标 → force-prune（剪到达标为止）
    force-prune 后仍不达标 → fail
```
- **三硬终止条件（防死循环）**：① 单原子 token > T（超窗）→ 直接 fail；② summarize 上限 N 用尽仍不达标 → 转 force-prune；③ force-prune 后仍不达标（理论极端）→ fail。
- **层级 1 生命周期剪除（首选，0 LLM，V1.5）**：按 5.11 剪 PRUNABLE 闭包（已完成任务、无外部依赖），整体移除 + 写墓碑；**常态 0-LLM 路径**。
- **层级 2 summarize-critical（次选，1 次 LLM）**：仅当无 PRUNABLE 闭包（全部是活跃任务）时才触发。对最老 critical 链（lastRefRound 最小的闭包连通子图，规模 ≤10 原子且 ≤2×超预算量）调一次 LLM 生成**摘要原子 S**：
  ① 只重定向外部入边 e=(x→y, critical)（x∉chain, x∈K）为 e'=(x→S)，chain 内边入摘要日志；
  ② S 编号递增、selfImportance=链内最大 critical 权重（effective=10 排序垫底）、lastRefRound=当前轮；
  ③ chain 原子 in_degree 清零入候选。
  **summarize 上限 N 默认 3 次**（每次作用于一个最老 critical 链）；摘要原子 S 可设目标长度（如 ≤ 链总 token 的 30%），支撑压缩率可控卖点。
- **层级 3 force-prune（最后）**：忽略闭包约束，按 ①等级 ②importance ③lastRefRound 强制剪最弱 critical 原子（**保留最新 U**）；**审计记录 + alert hook + 单次 force 数阈值告警**；不物理删除，入 recall 检索范围（5.10），日志含一句话摘要作锚点。
- **层级 4 fail（兜底）**：单原子 token > T 或降级循环用尽仍不达标 → 终止剪枝、明确报错提示新会话。
- **配置**：`degradationStrategy ∈ {lifecycle, summarize_critical, force_prune, fail}`，默认 lifecycle；lifecycle 为首选，无 PRUNABLE 闭包时自动降级到 summarize_critical。

### 5.10 剪枝视图恢复机制
**动机**：被剪原子物理仍在 JSONL（剪枝=发送视图），但需设计恢复通道，否则信息永久不可达。

- **工具定义**：`recall(query: string, maxTokens?: int)`，作为 customTool 注入 Agent；检索被剪原子存储 = **JSONL + 剪枝日志索引**（默认）；**若 memory 模式启用，追加记忆层为第二检索源**（条目无编号、仅内容锚点，命中经 archived 映射以 R_recall 注入），单机 ≤10k 消息顺序搜索即可；单次结果 ≤5% window（摘要+截断全文），每轮 ≤3 次、累计 ≤10% window。
- **注入生命周期**：结果作为 `R_recall` 原子**临时注入当前轮**（一次性），参与正常引用图与后续剪枝；不自动回填主上下文；被剪原子物理状态不变。
- **辅助回填通道**：剪枝日志保留被剪原子 refs；保留原子 refs 引用已剪编号（记忆残留）时，应用层可选 `auto_backfill`（默认 off，on 则摘要回填）或提示 Agent 调 recall。
- **与 Explorer 区分**：Explorer=文件系统浏览；recall=会话历史/被剪原子检索，命名与注册分离。
- **版本链剔除恢复（V1.7）**：5.13 diff 去重剔除的过往版本仍在 JSONL，recall 可恢复。
- **协同**：编号内联渲染 + 剪枝日志 = 检索锚点；recall 为被剪原子唯一访问通道——LLM 只能引用渲染视图内可见编号（V1.4 已采纳编号内联），被剪信息统一经 recall 访问；保留原子 refs 指向已剪编号（记忆残留）由应用层 refs 校验自动检出，触发 auto_backfill 或提示 recall。

### 5.11 闭包生命周期管理（V1.5，替代 summarize-critical 为首选降级）
**动机**：summarize-critical 在超预算时调用 LLM，破坏"压缩阶段 0 调用"的核心成本优势。生命周期管理让**已完成任务闭包整体剪除（0 LLM）**成为常态，summarize 退化为真极端兜底。

**闭包界定（扁平分区，不嵌套）**：
- 根锚 = 任务型 U（`¬askCover(U)`，复用 5.7 判定式）
- 边界三步：① 初界 = 根 U 至下一任务型 U 之间的轮次窗口（建图 O(1)）；② 收紧 = 仅保留与根弱连通的原子，孤岛划入"游离池"（不属任何闭包，永远可单独剪）；③ 组织 = 闭包内原子 + 跨闭包"借用边"（x∈C1→y∈C2），形成**闭包级依赖 DAG**
- **不嵌套**：嵌套引入归属歧义（共享原子归谁剪）与双重计数；扁平分区让剪除权唯一属于出生闭包，跨闭包依赖由全局 in_degree（不变量 3）统一钉住

**生命周期状态机**：
```
ACTIVE → COMPLETED → PRUNABLE → PRUNED
   ↑_________________________|
```
- **ACTIVE→COMPLETED**：静止信号——闭包内 `max(lastRefRound) ≤ 当前轮 − K`（K=2 默认可配）∧ 根非最新 U；max lastRefRound 随 5.8 建边顺带 O(1) 聚合
- **COMPLETED→PRUNABLE**：闭包 `in_degree==0`（无任何保留原子依赖其内原子），随剪枝单调递减
- **PRUNABLE→PRUNED**：超预算且候选耗尽时，按闭包 DAG 叶序剪最久未引用者，整体移除（0 LLM）；**落点按 5.12 closureDisposition 执行**（memory 写记忆层 / tips 留一句话 / tombstone 写墓碑）
- **任意→ACTIVE**：出现新入边（含 recall 注入 R_recall）拉回 ACTIVE；recall 后 K 轮内不重复剪（防抖动）
- 判定**动态**（每次建边/剪枝时惰性重算），信号全增量维护、**0 LLM**

**误判防护**：① K 轮宽限（连续静止才收尾）；② 即使误判，in_degree>0 的原子仍被不变量 3 硬挡；③ 剪除仅视图层、recall 可恢复——最坏损失一次 recall 调用而非数据；④ 最新任务 U 闭包永不 COMPLETED。

**降级路径重排（0 成本优先）**：
```
生命周期剪除（默认首选，0 LLM）：PRUNABLE 闭包整体移除
结论保留（0 LLM）：仅留根 U 原文/结论原子作闭包代表
summarize（最后手段，1 次 LLM）：仅当真活跃闭包也必须压缩时才触发
```

**可恢复性（墓碑）**：剪除写闭包墓碑 `{闭包ID, 根U原文, 原子清单, 剪除轮, 原因}`；**根 U 原文即 0-LLM 摘要锚点**，直接进 recall 索引；recall 命中注入 R_recall 并拉回 ACTIVE（保 K 轮）。长任务墓碑可选追加链内原子首句（仍 0 LLM），提升细节命中率。

**与 askCover / 不变量 2′ 的关系**：正交叠加——askCover 是原子级豁免，闭包生命周期是闭包级整体剪除，互不替代；剪除合法性由不变量 2′（边界无外入 critical 边）钉住。

### 5.12 闭包处置策略（V1.6，PRUNABLE→PRUNED 落点可配置）
**动机**：5.11 剪除闭包时统一写墓碑，未区分任务价值。处置策略让落点可配置，使闭包作为"完整任务收尾轨迹"发挥记忆价值；同时避免低价值闭包污染长期记忆。

**配置**：`closureDisposition ∈ {memory, tips, tombstone}`，默认 `tombstone`（与 V1.5 一致）；可全局配置，亦可按闭包类型覆盖（默认映射：task 型→memory、ask 型→tips、未匹配→tombstone，均可改；类型判定复用 5.7 判定式，不新增 LLM 标注税）。

| 模式 | PRUNED 落点 | 上下文残留 | LLM 成本 | recall 可达性 |
|---|---|---|---|---|
| memory | 闭包摘要写入记忆层，得 memoryId | 无 | 0（摘要 0-LLM 组装）；写调用为外部钩子 | 经 recall 双源命中，注入 R_recall |
| tips | 仅留一句话摘要原子 T_tips | 一句话原子（importance=1） | 0（复用结论首句） | 原文仍在 JSONL，可 recall |
| tombstone | 写墓碑进 recall 索引（现有 5.11） | 无 | 0 | 墓碑锚点命中 |

**memory 层抽象（ARGP 不关心实现）**：
```ts
writeClosureMemory(closureSummary: {rootU: string, keyAtoms: string[], conclusion: string, closureId: string}) → memoryId
```
**记忆层级语义**：闭包按"已收尾任务"落**长期层**（比单原子语义完整，作为独立记忆条目），非短期工作记忆。

**tips 生成规则（0 LLM）**：取闭包内结论原子（A）首句；无结论原子（异常）时降级为根 U 原文。T_tips 元数据记录其来源闭包。

**检索一致性边界**：① 记忆层条目**不带编号**，仅内容锚点；② 归档映射 `archived[闭包内编号→memoryId|T_tips]` 在建映射时登记；③ refs 校验：目标编号命中 archived → 判为"已归档引用"，不报残留，可提示经 recall 取回；④ recall 检索源 = JSONL+剪枝日志索引 ∪ 记忆层（仅 memory 模式启用时查记忆层，结果统一以 R_recall 注入，新编号全局递增）。

**与 5.11 关系**：5.11 的墓碑为 tombstone 专属路径；memory/tips 模式不写墓碑（或仅写轻量日志，内容已在记忆层/tips 承载）。

### 5.13 R 版本链 diff 去重（V1.7）
**动机**：read→edit→read、snapshot→Click→snapshot 产生大量高重叠 R 原子；原子级剪枝只决定"留哪些原子"，管不到原子间内容重复。
- **相似度判定**：重叠系数 `sim(A,B)=|A∩B|/min(|A|,|B|)`，行级 diff 公共行即分子，0 LLM；大幅增量(5000→6000)/减量(6000→100)一方为子集，sim 仍=1.0。工具信息仅作预筛（同工具才比），最终以 sim 为准。
- **版本链组织**：sim≥θ（默认 0.8，可配）归同一版本链；链维护公共基线 C（全版本行交集）+ 各版本 delta。
- **去重语义**：过往版本从视图剔除，仅保留最新版（全量或 C+delta 标注）；全量仍在 JSONL，经 recall 恢复（同 5.10）。
- **渲染规则**：视图内该链只渲染最新版，历史 delta 不渲染。
- **二进制/图片退化**：无法行级 diff → 内容 hash 相同=完全重复合并；hash 不同不合并。
- **交互**：①编号内联：仅渲染最新版编号，被剔除编号不出现在视图；②引用图：指向历史版本的边——critical 引用即保留（豁免剔除+日志），supporting/contextual 重定向最新版；③剪枝/闭包：去重（0 LLM）→图剪枝（0 LLM），均在压缩阶段完成，原子粒度不变；④askCover 不受影响；⑤其余内容管线策略（结构裁剪 head/tail、块级全局去重、密度分、snapshot 局部变化 vs 路由跳转）**待定**，不落盘。

## 6. 与 Pi Agent 的集成（V1.8：直接改造方案）

**方案转变（V1.8）**：由"SDK 外部集成"改为**直接改造 pi coding-agent 内部**。依据：pi 会话层为 JSONL entry 树（条目带 id/parentId、不可变追加、分支=移动 leaf），历史物理永在，压缩本就只是"视图边界条目"——正是 ARGP"剪枝=发送视图、非物理删除"的现成载体。原 R1 写回一致性、R3 流式对齐风险与假设 A5 由此消解；压缩后写回 agent 消息状态为 pi 既有机制，直接复用。

| 集成点 | 做法 | 风险 |
|---|---|---|
| 原子化 | 无需事件订阅：遍历 JSONL 会话条目原子化——user→U、assistant→A（其 content 内 toolCall block→T）、toolResult→R；确定性边 A→T、T↔R 经 toolCallId 由条目结构推导 | 特殊条目（bashExecution/custom/branch_summary 等）需映射规则 |
| 编号推导 | 编号按当前分支 entry 路径顺序派生、可重算不落盘；被剪原子编号保留 | 不同分支同一 entry 编号不同，视图自洽可接受 |
| 引用声明 | system prompt 追加输出契约（只引用可见 `[编号]` + 尾部 refs JSON）；assistant 落盘时解析 refs 写 entry details 并从渲染剥离 | R2 LLM 格式漂移（容错兜底空 refs） |
| 剪枝执行 | 替代原摘要式压缩管线：剪枝结果写"剪枝边界条目"（保留 entry ID 集合+原子映射+剪枝日志）入 JSONL，替代原 CompactionEntry；常规路径 0 LLM | — |
| 视图重建与编号内联 | 上下文重建遇剪枝边界条目→按保留集重建消息，投影 `[编号] 内容` 进 LLM 上下文，再写回 agent 消息状态 | R4 编号一致性（渲染层保证） |
| recall 工具 | 原生工具 recall(query)：经剪枝日志+JSONL 检索被剪原子，以 R_recall 注入当前轮 | 结果 token 上限+轮次频控（5.10） |
| 降级 | 候选耗尽内联执行降级序列：生命周期剪除（5.11，验证期缓）→summarize-critical→force_prune→fail；summarize 复用既有简单补全调用 | summarize 的 LLM 异常路径 |

**语义边持久化**：refs 落盘于所属 assistant entry 的 details 字段（不新增条目类型）；确定性边+已持久化语义边可在会话 reload、分支导航、resume 后完整重建引用图。

**验证期实现范围（技术验证）**：本期实现 5.1–5.10（5.7 判定式为纯图算法，一并实现）；5.11 闭包生命周期、5.12 处置策略、5.13 R 版本链去重、头脑风暴模式缓至二期。验证期降级序列为 summarize_critical→force_prune→fail（无 lifecycle 层级），"持续降级直到达标"语义不变。

**对验证计划的影响**：阶段 1 项①"写回一致性"在本方案下变为"剪枝边界条目写入→reload→分支导航后会话重建一致性"（确定性校验，非抽样通过率指标）；其余项不变。

## 7. 验证计划（外部验证核心）

### 阶段 1：Spike 可行性（0.5–1 天）
- **目标**：验证三个技术前提（写回一致性、refs 格式稳定率、标注税占比）
- **前置**：Pi SDK 环境；种子场景脚本（5 类任务 × 20 轮）
- **步骤**：① 剪枝→写回→重启会话→读取比对，共 100 次；② 100 轮对话统计 refs JSON 解析成功率（含重试 1 次后的恢复率）；③ 测量 `refs+importance` token / 每轮总 token（不含索引，索引税已归零）；④ 统计保留集内联渲染后 LLM 输出 refs 中"指向可见编号"的正确率
- **通过标准**：① 写回一致率 ≥99%；② refs 稳定率 ≥95%；③ 标注税 ≤40 token/轮 且 ≤8% 每轮总 token；④ 内联编号引用正确率 ≥95%（不产生不存在的编号）
- **风险/止损**：若①<90% 且无 workaround → 方案在 Pi SDK 不可落地，转自研会话层；止损 ≤0.5 天

### 阶段 2：真值测试（1–2 天）
- **目标**：验证剪枝保真度（不变量 2 的实际效果）
- **前置**：阶段 1 通过；构造 30 组已知依赖对话（每组埋 3–8 条 critical、5–10 条 supporting 真值边）
- **步骤**：分别以 30%/50%/70% 压缩率剪枝，对照真值边检查
- **指标**：critical 闭包完整率 = 剪后保留的 critical 真值边 / 全部；结论可复现率 = 由剪后上下文 LLM 复现原结论的正确率
- **通过标准**：30% 压缩率下闭包完整率 ≥98%、可复现率 ≥95%；50% 下 ≥95%/≥90%；70% 下 ≥90%/≥80%
- **风险/止损**：30% 压缩率下闭包完整率 <90% → LLM 引用不可靠或闭包算法缺陷；止损 ≤1 天，失败则回退 importance-only 剪枝作对照基线

**阶段 2 专项：ask 降级验证（+0.5 天）**
- **目标**：验证 5.7 ask 覆盖豁免规则的实际效果（不误伤非 ask，且信息可替代）
- **前置**：在 30 组真值对话中另构造 ≥10 组 ask 型 U（5 组真 ask + 5 组"占位回复"诱饵）
- **步骤**：以 50%/70% 压缩率剪枝，对照检查
- **指标**：① 闭包完整率（豁免不误伤非 ask）；② ask 信息回忆率 = 剪后由 A_{i+1} 复述 U_i 内容的正确率
- **通过标准**：真 ask 组回忆率 ≥90%，诱饵组误剪率 ≤10%（证明误判可被检出）
- **风险/止损**：诱饵误剪率 >10% → 判定式过于宽松，收紧为"需 LLM covers 标志辅助"；止损 ≤0.5 天

**阶段 2 专项：时间降级验证（+0.5 天）**
- **目标**：验证 5.8 时间降级维度的实际效果（活性度量正确，不误伤近期活跃原子）
- **前置**：构造 10 组对比对——(A) 早期创建但近期被引用（lastRefRound 近）vs (B) 近期创建但从未被引用（距离大），level/importance 相同
- **步骤**：以 50%/70% 压缩率剪枝，对照检查
- **指标**：① lastRefRound 建边更新正确率；② B 先于 A 被剪一致率；③ 引入后 critical 闭包完整率
- **通过标准**：① 正确率 100%；② 一致率 ≥90%；③ 闭包完整率不低于阶段 2 主指标基线
- **风险/止损**：② <80% → 排序键 ③ 引入噪声，评估回退 createdAt 或调整权重；止损 ≤0.5 天

**阶段 2 专项：降级策略验证（+0.5 天）**
- **目标**：验证 5.9 降级策略（生命周期剪除/summarize-critical 重定向/force-prune 审计/fail 兜底）
- **前置**：构造 10 组全 critical 高密度对话（含 2 组单原子超窗）
- **步骤**：四配置（lifecycle / summarize_critical / force_prune / fail）各触发一次，对照检查
- **指标**：① 无 API 溢出率；② 重定向不漏边率；③ 降级后结论可复现率；④ force 审计日志完整率；⑤ lifecycle 路径 0-LLM 率
- **通过标准**：① 无 API 溢出 100%；② 重定向不漏边 ≥98%；③ 降级后结论可复现 ≥85%；④ force 审计日志完整率 100%；⑤ lifecycle 触发时 0-LLM 路径占比 ≥80%
- **风险/止损**：③ <80% → 收紧 summarize 输入规模或回退 force_prune；⑤ <60% → K 值过大导致 PRUNABLE 闭包过少，调小 K；止损 ≤0.5 天

**阶段 2 专项：闭包生命周期验证（+0.5 天）**
- **目标**：验证 5.11 闭包生命周期管理（界定正确性、静止信号判定、墓碑 recall 恢复）
- **前置**：构造 20 组多任务对话（每组 3-5 个任务闭包，含跨闭包借用边、游离池原子）
- **步骤**：以 50%/70% 压缩率剪枝，检查闭包状态转换与剪除
- **指标**：① 闭包界定正确率（归属无误并包/漏包）；② ACTIVE→COMPLETED 判定一致率（K=2 静止信号 vs 人工标注）；③ 墓碑 recall 命中率；④ 跨闭包借用边剪除顺序正确率
- **通过标准**：① ≥95%；② ≥90%；③ ≥90%（根 U 原文锚点）；④ 100%（借用者先于被借用者剪）
- **风险/止损**：② <80% → 调整 K 或加"新入边拉回 ACTIVE"的时序检查；止损 ≤0.5 天

**阶段 2 专项：恢复机制验证（+0.5 天）**

- **前置**：30 组真值对话随机剪 ≥20 原子；逐原子构造 query
- **步骤**：对每个被剪原子构造 recall 查询，检查命中与注入后复述
- **指标**：① recall 命中率（top3）；② 注入后复述正确率；③ 预算增幅
- **通过标准**：① 命中率 ≥90%；② 复述正确率 ≥85%；③ 预算增幅 ≤10% window 100%
- **风险/止损**：① <80% → 为被剪原子补一句话摘要索引（增强锚点）；止损 ≤0.5 天

**阶段 2 专项：处置策略验证（+0.5 天）**
- **目标**：验证 5.12 三模式落点正确、记忆层 recall 可恢复、refs 校验无误报
- **前置**：20 组多任务对话；三模式各配 1/3 闭包，含跨闭包借用边与 archived 映射
- **步骤**：50%/70% 压缩剪除后：① 检查落点符合 disposition；② memory 闭包经 recall 命中记忆层并复述结论；③ tips 原子被后续剪枝正确剪除且可从 JSONL 恢复；④ 保留原子 refs 指向已归档编号时不误报残留
- **指标**：① 落点一致率；② 记忆层 recall 命中率、结论复述正确率；③ tips 恢复率；④ 残留误报率
- **通过标准**：① 100%；② 命中率 ≥90%、复述正确率 ≥85%；③ 恢复率 100%；④ 误报率 ≤5%
- **风险/止损**：② <80% → 摘要加长或改带编号方案；④ >10% → archived 映射遗漏，检查登记时机；止损 ≤0.5 天

**阶段 2 专项：diff 去重验证（+0.5 天）**
- **目标**：验证 5.13 判定/组织/剔除后引用语义
- **前置**：20 组 read→edit→read 与 snapshot→Click→snapshot 对话（含大幅增/减、二进制返回、跨工具同内容）
- **步骤**：①重叠系数 vs 人工标注一致率；②版本链归并正确率；③剔除+重定向后结论可复现率；④二进制 hash 退化正确率
- **通过标准**：①≥90%；②≥95%；③≥90%；④100%
- **止损**：③<80% → 默认改"引用即保留"而非重定向；止损 ≤0.5 天

### 阶段 3：A/B 端到端（2–3 天）
- **目标**：验证真实收益
- **前置**：阶段 2 通过；≥20 个多轮任务（每个 ≥10 轮）
- **三组**：无压缩 / SDK compact / ARGP
- **指标**：任务完成率、总 token、端到端延迟 P50、压缩后细节回忆率（压缩后追问早期细节的正确率）
- **通过标准**：ARGP vs SDK compact——总 token 降低 ≥20%、延迟降低 ≥15%、任务完成率 ≥compact 的 95%、细节回忆率 ≥compact 的 90%
- **风险/止损**：ARGP 任务完成率相对无压缩组下降 >15% → 标注税/索引引入噪声；止损 ≤3 天
