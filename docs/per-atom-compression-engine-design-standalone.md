# 逐原子压缩引擎设计（自包含版）

> 本版本为**自包含**设计说明：不依赖任何特定项目的既有上下文，概念均在文中定义。适用对象：长会话智能体（coding agent / 任务型 agent）的上下文管理。
> 配套版本：项目内嵌版（含与既有系统的对接细节）见 `per-atom-compression-engine-design.md`。

---

## 0. 问题背景

长会话智能体（连续 50-100+ 轮工具调用）的上下文随时间线性膨胀，两个结构性事实：

1. **工具结果是上下文绝对大头**：一轮对话通常包含"用户指令 + 工具调用 + 工具结果 + 模型回复"。其中工具结果（文件内容、命令输出、日志、查询结果）常占一轮内容的 **80-97%**。实测典型值：一轮 4K token 的增量中，工具结果占 3.8K+。
2. **现有两类方案的失效模式**：
   - **纯剪枝（删除）**：删除低价值内容腾空间 → 信息不可恢复，精确内容（路径、行号、错误码、token、marker）一旦删除即丢失。
   - **纯摘要**：把旧内容压成摘要 → 精确内容被破坏，且摘要化替换发生在上下文中段 → 每次替换都击穿模型服务端的提示词前缀缓存。

**目标**：
- 会话长度与上下文增长**解耦**（支撑 5-10× 轮数）
- 信息**可达性不丢**（任何被压缩内容可恢复原文）
- 缓存经济**保持**（前缀稳定，跨轮命中累积）

## 1. 核心思想：两阶段压缩

完整压缩引擎 = 两个阶段：

```
Stage-1 熵降（每轮结束，eager，LLM 参与）
    └─ 对当轮原子逐个做有损但可恢复的压缩（降信息熵）
Stage-2 组图剪枝（上下文到达上限时，lazy，纯确定性）
    └─ 在熵降后的原子集上构建依赖图，按图做保留/剪除决策
```

- **剪枝 = 删除**（信息丢失）；**熵降 = 有损压缩**（信息保底、可升级恢复）。
- Stage-2 完全确定性（0 LLM 调用），保证压缩事务的可复现性与成本稳定。

## 2. 原子分类与处理策略

"原子" = 一条不可再分的对话单元：用户消息、工具结果、模型回复。逐原子决策：

| 原子类型 | 处理 | 理由 |
|---|---|---|
| 用户消息（短，≤100 字符） | **原样保留** | 指令/简单对话，体积小且必须精确 |
| 用户消息（长，>100 字符） | **LLM 拆分**为 `info` 与 `dialog` 两部分 | 长消息通常=粘贴的外部资料（文章/表格/方案）+ 真正的指令；**指令（dialog）必须原文幸存**，资料（info）允许有损压缩 |
| 工具结果 | `need_compress = false / summary / extract` | 三档策略（见 §3） |
| 工具结果（**版本链成员**） | **强制 `false`** | 参与内容版本链/哈希去重的结果依赖原文（哈希、逐版本比对要求 verbatim），绝不压缩 |
| 模型回复 | **不压缩** | 体积小；且是后续轮次的工作对象（计划/决策/结论），有损压缩会破坏对话流连续性 |

**为什么模型回复不压缩**：①通常只有几百字符，压缩省不了多少；②它是后续轮次直接引用的内容，破坏它等于破坏对话的主干。

**info/dialog 拆分的原子模型**：拆分产**两类语义不同的原子**，但**不发明新事件类型**——全部落在宿主平台原生事件上，用前缀 flag 区分子类：

| 平台原生事件 | 剪枝分类 | 语义 | 剪枝待遇 |
|---|---|---|---|
| 用户消息（无 flag） | U | dialog（指令） | 永不剪 |
| 用户消息（`argp.info=true`） | U-info | info（参考资料） | **可压缩、可剪**、低权重 |
| 模型回复 | A | 回复 | 不压缩、图节点 |
| 工具结果 | R | 工具结果 | 门控压缩，可剪（版本链除外） |
| 工具调用 | — | 不进模型可见面，无独立原子 | 与回复配对 |

- **归属**：两条原子共享 `turn = 原轮` + `sourceSeq = 原始用户消息编号`；原始用户消息全文留不可变日志（= 原文召回的恢复目标）。
- **引擎改动（唯一）**：剪枝候选判定对"用户消息 + info flag"放行（按工具结果待遇可剪），其余用户消息保持永不剪。
- **自然边**：拆分调用顺带产出 `dialog → info` 边（指令依赖所贴内容）——info 在指令存活期内受保护，指令被消费/过新后保护随边衰减，info 恢复可剪状态。
- **后续引用**：info 可被后续原子引用（被引用则入图保护）。
- **保真风险**：拆分误判（指令内容进了 info 会被压缩掉）→ 拆分提示词采用保守策略（不确定归 dialog）+ 提取保留关键精确串。

## 3. need_compress 门控（确定性门控 + LLM 动作）

门控全部**确定性**（零成本），LLM 只执行摘要/提取**动作**。决策顺序：

1. **版本链成员 → `false`（硬排除）**：内容完整性优先。
2. **工具作者声明** → **上限提示**（非强制）：作者声明"本工具结果可压/可提取"。
3. **未声明 → 大小启发式默认**：小结果 → `false`；大结果 → `extract`。
4. **图重要性可覆盖**（Stage-2 组图后）：被大量引用/高价值原子即使声明可压也保留原文。

三档语义：
- `false`：原文保留，不压缩
- `summary`：LLM 生成摘要（内容大意，丢失精确细节）
- `extract`：LLM 只保留**最关键的一两句原文**（保留精确串，丢失其余）

> **建议 extract 优先于 summary**：agentic 场景下游经常需要精确内容（路径/行号/错误码/token）。extract 保留"最可能被再用的那几句原文"，是保真与体积的最佳折中。

**调用门控（省调用）**：per-turn 的 LLM 压缩调用**仅当轮存在可压缩原子才触发**：

```
可压缩 = 任一用户消息 >100 字符 ∨ 任一工具结果 need_compress ∈ {summary, extract}
```

纯对话轮（短指令 + 回复、无工具结果）**直接跳过**——零压缩成本、零边声明。代价：此类轮次不产边，长程跨轮依赖可能漏——缓解：此类原子受新近度保护（剪枝时靠后），必要时由全局组图兜底（§7）。**成本含义**：压缩成本从"每轮固定付费"变"按需付费"，平均值大幅下降（§9）。

## 4. 处理时机与缓存语义（tail-only 替换）

**时机**：每轮对话结束后，立即处理**当轮的原子**（位于上下文"尾部"）。

**缓存语义（关键）**：模型服务端对提示词前缀做 KV 缓存。当轮原子位于上下文尾部，替换它们**不改变前缀**：

```
下一轮请求 = [前 N-1 轮 原样前缀] + [第 N 轮 压缩版] + [新内容]
              └────── token 序列未变 → 全部缓存命中 ──────┘
```

- 只有"第 N 轮压缩版 + 新内容"是未命中（miss），前缀全部命中（hit）。
- 压缩版落盘后**稳定**，后续轮次继续命中它 → 跨轮缓存累积保持。

**对比中段替换**：若替换的是早期/中部内容（前缀改变），其后所有 KV 失效 → 整段重处理（全量 miss）。**tail-only 替换的缓存画像严格更优**。

**例外**：版本链原子 / 高价值原子留在原位，不触发替换。

## 5. 三级存储与两级召回（渐进 zoom）

每个被压缩原子产生三级内容：

| 级别 | 内容 | 存放 | 消费方 |
|---|---|---|---|
| **extract** | 1-2 句关键原文（最小） | 上下文 surface（常驻） | 模型直接可见 |
| **summary** | 压缩时生成的摘要 | 随原子存储 | 召回（gist 档） |
| **original** | verbatim 全文 | 不可变日志 | 召回（detail 档） |

**两级召回**（"渐进 zoom"）：

| 工具 | 返回 | 成本 | 语义 |
|---|---|---|---|
| `recall_summary(seq)` | 摘要 | 输出 ~1K token | "这内容是关于什么的"（gist） |
| `recall_detail(seq)` | 原文 verbatim | 输出=全文（最大可达数十 K token） | "确切字符串"（exact） |

- **verbatim 天花板**：detail 档永远存在——精确内容不会因压缩而不可达，只付出一次升级成本。
- **升级策略**：工具描述教模型区分——gist 查询用 summary，exact 查询用 detail。误用 detail 会贵；该用 detail 而停在 summary 会答错。
- **分档预算**：召回有字数预算，两档分设（summary 便宜多给 / detail 贵少给），防止模型滥用。
- **闭环**：召回结果重新进入上下文（尾部追加，缓存友好），**本身再次成为可压缩原子** → 压缩-召回闭环，不因召回重新撑爆上下文。

## 6. 插件生态安全（防干涉要求）

若系统是多插件生态（多个插件注册工具、共享会话），压缩不得干涉其他插件的读写。设计要求：

1. **压缩副本仅对模型可见（model-only）**：压缩/替换副本只进"模型视图"；原始内容保留在不可变日志中，UI 展示、持久化、其他插件一律读原文。平台需保证"替换副本 model-only、原始事件可回溯"。
2. **声明通道独立**：工具压缩策略通过**专用注册接口**声明（如 `setToolPolicy(toolName, policy)`），**不塞进工具结果载荷**、不改工具定义 schema。
3. **命名空间隔离**：策略字段/元数据使用**前缀命名空间**（如 `xxx.*`），杜绝与其他插件字段名冲突。
4. **声明 = 提示，不是命令**：图重要性可覆盖错误声明。
5. **缺席默认 verbatim**：未声明的工具行为零变化，保持原有路径。
6. **实测验证**：挂一个"观察插件"读不可变日志，断言压缩后原文仍在——把"架构上能排除"升级为"实测已排除"。

### 6.1 工具对照表（tool 对照表 / `setToolPolicy`）

**问题**：§6-2 声明了"工具作者可声明压缩档位"，但**哪些工具该声明、声明成什么档**没有给决策依据。尤其 shell 这类异构工具——输出形态完全取决于命令（`ls` 是文件名列表、`grep` 是命中行、`npm test` 是海量日志、`curl` 是任意 body），**无法预先判断它该 extract 还是 summary**。

**核心立场：对照表是"提示"不是"清单"，且刻意稀疏。** 三层防线里它排第 2 层，第 1 层（版本链硬排除）与第 3 层（保真守卫）都是**不依赖声明的确定性安全网**——所以**绝大多数工具可以不声明**，落回大小启发式 + 守卫兜底（§6-5 缺席默认）。声明只在"启发式默认明显不对"时才值得加。

**决策矩阵（哪些工具值得预设）**：

| 工具类型 | 输出形态 | 该声明吗 | 建议档位 | 理由 |
|---|---|---|---|---|
| `read_file`（读已知文本） | 形态稳定、常大 | **是** | `extract` | 大文件结果最常见、extract 收益最大、形态可预测——唯一"高置信"该声明的常见工具 |
| `grep` / 搜索 | 命中行，每行常含高信号 token | 否（或 `extract`） | — | 启发式已够；若命中极少行、守卫常拒，可声明 `extract` 提示模型逐行保 token |
| **shell / bash** | **完全异构**（列表/日志/body/错误） | **否——刻意不预设** | — | 见下方论证。声明 `extract` 会诱导模型对纯叙述输出也强行摘取；声明 `false` 会漏掉大日志的可压机会。两害都真实，故**不声明**，交给"大小启发式定候选 + 保真守卫定落盘" |
| `web_fetch` / API 查询 | JSON/HTML，形态不定 | 否（或按 endpoint 细分子策略） | — | 同 shell；除非能按 URL 模式细分，否则不预设 |
| 版本链敏感工具（`git`/哈希比对/去重） | 依赖原文 verbatim | 否（被第 1 层覆盖） | `false` | 版本链硬排除已强制 `false`，无需声明 |

**shell 为何刻意不预设（关键论证）**：

1. **声明只能"二选一"，而 shell 输出横跨两个极端。** `ls` 输出（几十行短路径）和 `npm test` 输出（数千行日志）用同一个 `bash` 工具名。声明 `extract` → 对 `ls` 这种小结果守卫会拒（没东西可摘），对大日志才有意义；声明 `false` → 大日志的可压机会被永久放弃。一个静态档位无法同时对两种形态正确。
2. **真正的安全网不依赖声明。** 大 shell 日志能压，靠的是：①大小启发式把它选进候选（>512 字）；②模型产出 extract；③保真守卫**逐 token 校验**——丢任何高信号 token 就拒绝、原文保面。这套"启发式选候选 + 模型提草案 + 守卫定生死"对 shell 已经安全，**声明并不增加安全性，只增加错误方向的诱导**。
3. **声明错档的代价是"白压"或"漏压"，且难发现。** T1（read_file 读日志）的白压正是"提示词诱导摘要式压缩 + 守卫拒绝"的产物（见 review 严重发现）。若给 shell 预设 `extract`，等于把同样的诱导施加到所有 shell 输出上，放大了这类风险。

**结论**：tool 对照表**默认留空**（§6-5 缺席默认）。仅对**形态稳定且大、extract 收益确定的工具**（典型就是 `read_file`）声明 `extract`。shell / web_fetch 等异构工具**不预设**，靠"大小启发式 + 保真守卫"两层不依赖声明的安全网兜底。这与 §6-4"声明 = 提示非命令"、§6-5"缺席默认 verbatim"一致：**对照表越稀疏，系统越安全**。

**实现状态（2026-08-25 已接通）**：`PeratomCompressor.setToolPolicy(toolName, policy)` 公开 API + 构造期 `toolPolicies` 注入；`GateToolResult.toolName` 经 `callId→name` 反查挂上原子（`buildToolNameIndex`）；`rNeedCompress` 按 `toolName`（非 callId）查表，声明只放宽/收紧启发式、不可越过版本链硬排除。单测见 `test/peratom-gate.test.ts`（按 toolName 命中 / 无名字跳过启发式）与 `test/peratom-compressor.test.ts`（setToolPolicy 即时影响 collect + 撤销回启发式 + shell 未声明走启发式）。

## 7. 组图：边声明搭便车 + 全局备选

Stage-2 的图（哪些原子依赖哪些原子）构建方式：

**主方案（搭便车，推荐）**：Stage-1 的 per-turn LLM 压缩调用**本来就存在**，让它在产出压缩结果的同时，**schema 强制**地顺带声明当前内容的依赖边（`cites: [{目标原子, 强度}]`）。收益：

- **边际成本≈0**：边声明只是压缩调用输出的一个小字段。
- **服从率可靠**：压缩调用是结构化调用（schema 强制输出），远高于自由文本里让模型"记得声明依赖"的服从率。
- **图逐轮增量构建** → 上下文到达上限时图已就绪 → **最终压缩纯确定性（无额外 LLM 调用）**。
- **构建器视野**：压缩调用输入 = 当轮原子 + **近期上下文摘要**（§5 的 extract 级内容，小而可读）→ 可按原子编号声明依赖。
- **已知局限**：局部视角（当轮 + 近期窗口），长程跨轮依赖可能漏检 → 缓解：输入窗口拉长（摘要很便宜，可喂 10-20 轮）+ 接受局部近似（agentic 依赖绝大多数是局部的）。
- **孤立原子规则**：**跳过压缩调用的轮次（§3 门控：纯对话轮）= 孤立原子**——同一谓词两个效果：①省调用；②**不建轮内边**（题外话/答疑不产生自引用保护，防止污染图），原子为叶节点低权重，仅受新近度保护。被后续原子引用时**正常入图**（获得引用度按边保护）。安全网：用户指令原子永不剪（关键约束天然安全）+ 新近度保护 + 引用入图 + 原文召回兜底。判定边界：长用户消息（>100，触发拆分）或有工具结果的轮次**不算孤立**，正常建边。

**备选（全局组图）**：若局部视角经验证不够，退回"上下文到达上限时批量组图"——图构建器读全量（熵降后）原子，一次产出完整边集。成本 = 每次压缩一次 LLM 调用（输入已熵降、小 5-10 倍）；质量 = 全局视角。两方案共用同一注入与剪枝管线。

**部署拓扑（双引擎双插件，已决策）**：压缩产出与 cites 声明**无数据耦合**（双向检查：cites 只需原子编号 + extract 级内容视图；压缩不需要 cites 结果），唯一共享物是触发谓词（可由共用门控模块提供）。据此拆分为两个独立插件：

- `peratom-compressor`：Stage-1 熵降管线（§2-§5）
- `cite-declarer`：边声明管线（本节搭便车逻辑独立成插件）

代价："边际成本≈0"修正为**低边际成本**——每可压缩轮多 1 次轻量调用（lite 档/短输入可控）。收益：① cites 独立关断（价值验证失败时一键下线，不动压缩引擎）；② 契约独立演化；③ 失败隔离（cites 解析失败不阻塞压缩）。与宿主平台既有 argp-contract / argp-cites 契约分离先例同构。

## 8. 最终压缩流程（上下文到达上限时）

**常规路径（渐进到达上限）**：
1. 图已就绪（搭便车增量，或全局补图）。
2. 按图 + 静态信号（引用度、新近度、原子类型权重）做**反向拓扑**排序，确定剪除顺序。
3. 确定性剪枝：低价值原子替换为占位符（可经召回恢复原文）。
4. 版本链 / 高价值原子天然保留。
5. 剪枝后新 surface 继续服务下一轮 → 回到 §4 的缓存累积循环。

**溢出路径（单轮内容直接超窗口，如单条超大工具结果 / 超大粘贴）**：
1. **先判断图是否可用**：图存在且有可剪候选（过了保护期的旧内容）→ 0-LLM 图剪枝先释放空间（便宜、快）。
2. **图不可用 / 剪后仍超** → 对**当前轮大原子降熵**（extract/summary）——硬约束：当前轮原子受新近度/轮次保护**不可剪**，溢出内容只能靠降熵；这也是边声明（搭便车）的产出时机（提前到溢出时）。
3. **降熵后仍超** → 在熵降后的表面上再执行图剪枝。

> 关键约束：**当前轮原子不可剪**决定了溢出路径必然包含降熵——图剪枝只能先清旧内容，压不动新的大原子。

**完整性**：Stage-1（熵降，顺带建图）+ Stage-2（确定性剪枝）= 完整压缩引擎。

## 9. 成本分析（示例价格模型）

以常见的"输入未命中 ¥1.5/M、缓存命中 ¥0.05/M、输出 ¥4.5/M"（miss/hit 价差 30×）为例：

| 维度 | 本方案（每轮熵降，含调用门控） | 传统（溢出才压缩） |
|---|---|---|
| 每轮输入成本 | miss ~5K（≈¥0.0075）+ 熵降 LLM **按需触发**（§3 门控：~30% 轮次 × ≈¥0.02）→ **均值 ≈¥0.012-0.014**（全触发上界 ¥0.027） | miss 4K（≈¥0.006）+ 前缀命中累积（便宜）≈ **¥0.008** |
| 100 轮总账 | ≈¥1.4（均值） | ≈¥2.2（含数次大窗口全量击穿 ≈¥1.2） |
| 会话长度 | **5-10×**（extract 级压缩） | 受窗口上限卡死 |
| 缓存画像 | 前缀保持命中 | 压缩时全量击穿 |
| 窗口需求 | 小窗口（如 32K）可行 | 需大窗口（如 160K） |

**5-10× 轮数的算术依据**：工具结果占增量 85%+、extract 压到原尺寸 5-10% → 每轮增长降到约 12-19% → 可支撑轮数放大 5-8×。**压缩比是命门**——两级召回（§5）解锁更激进的 extract（信息可达性不丢，只延迟），使高压缩比安全可用。

> 数值为示例先验，最终以 §10 的双 regime 实测为准。

## 10. 验证方案

1. **双 regime A/B**：同一任务、同一模型，跑"每轮熵降"与"溢出才压缩"两版引擎，比三件事：
   - 成本三元组（miss / hit / out）
   - **最大可持续轮数**（会话长度轴）
   - 任务质量（保真轴）
2. **探针套件**（三类）：
   - **exact 探针**：验证 detail 档召回可靠（verbatim 天花板成立）
   - **gist 探针**：验证 summary 档价值（只问大意、不问精确串）
   - **extract 保真探针**：验证关键精确串（路径/行号/错误码/marker）被 extract 保留的比例
3. **防干涉验证**（§6-6）：观察插件断言压缩后原文仍在不可变日志。

## 11. 设计决策记录（2026-08-24 逐条裁定，原开放问题）

1. **info 压缩动作**：拆分调用顺带 LLM 标注三档（false/summary/extract），§3 确定性门控做上限提示——搭便车模式第三次复用（压缩顺带 cites、拆分顺带档位标注）。
2. **拆分阈值**：固定 100 字符起步，实测后校准。
3. **extract 保真串**：四类起步——路径 / 行号 / 错误码 / marker（含标识符、URL、哈希）。
4. **版本链成员判定**：内容哈希复用宿主机制。
5. **召回预算**：4 倍制——summary 档总预算 = 4× detail 档。
6. **建图窗口**：局部视角 10 轮 extract 级摘要窗口起步；全局补图（§7 备选）**延后决策与实现**——与现管线耦合度低，不阻塞首版。
7. **再压缩**：**禁止二次压缩**——每个 info/tool result 只有两种形态（detail 原文 / summary·extract 压缩态）；召回可选任一形态；surface 上为压缩态时仍可召回 detail。无多级退化链。

> 决策 7 对 §5 的修订：三级存储中 summary/extract 是同一"压缩态"的两个变体（互斥，由门控决定），不是叠加层级；剪枝占位符是第三种表面形态但属于 Stage-2 删除语义，非压缩退化。

## 12. 术语表

| 术语 | 定义 |
|---|---|
| 原子 | 一条对话单元：用户消息 / 工具结果 / 模型回复 |
| surface | 当前对模型可见的上下文（压缩后的视图） |
| tail-only 替换 | 只替换上下文尾部（最新）原子，保持前缀不变 |
| 缓存命中/未命中 | 服务端对提示词前缀的 KV 复用（hit / miss） |
| entropy（熵降） | 有损压缩使原子变小，但保留恢复路径 |
| 版本链 | 内容按版本连续追踪、依赖哈希/逐版本比对的结构 |
| verbatim | 未经任何处理的原文 |
| 边（依赖图） | 原子之间的依赖关系（"A 依赖 B"） |
| 反向拓扑剪枝 | 按依赖图从叶子（无依赖者）向根剪除的确定性算法 |
